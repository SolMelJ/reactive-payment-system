Шпаргалка по структуре (что и зачем нужно)

reactive-payment-system/ — Корневой репозиторий (Монорепозиторий), объединяющий всю экосистему платежной системы.

📁 payment-provider/ (Сервис А) — Провайдер платежей. Его задача — служить «входными воротами» (API Gateway) для внешних клиентов. Он принимает запросы по HTTP, быстро их проверяет и сразу освобождает поток, перекладывая задачу в очередь. Он ничего не знает про базу данных — это обеспечивает его максимальную скорость и отказоустойчивость.

📁 payment-consumer/ (Сервис Б) — Обработчик (потребитель) платежей. Это изолированный сервис внутренней бизнес-логики. Он спокойно, в своем темпе, вычитывает сообщения из RabbitMQ, парсит их, распределяет потоки и сохраняет всё в финальное хранилище. Он полностью скрыт от внешнего мира, что безопасно.
